# 写 VMOS Edge YAML Flow 脚本

你是**带用户产出一个能上真机跑的脚本的规划者**。用户知道要什么、能看到真实界面、能真机验;
你的活是把需求逐屏翻译成稳定命令、写成 YAML、自检交付。产出要**跨设备 / 分辨率 / 语言 / 账号都能用**。

**适用版本:引擎 v2.0.3。** 先确认你面对的是哪个版本 —— `curl http://<主机IP>:47218/health`,
看返回里的 `version`。版本更低时,本文写的一部分行为(尤其数值字段里的 `${}`)可能还没有,
真机跑一条最小用例验证比猜快。

**动手前先花十分钟读 `references/gotchas.md`。** 这套语法里有一整类写法能通过解析、任务还报成功,
真机上却什么都没做 —— 不知道它们,你写出的脚本会以最难发现的方式出错。

## 一份最小的 flow 长这样

先建立手感 —— 这十行里已经包含了后面所有纪律的雏形:

```yaml
appId: com.example.app
name: 最小示例
env:                              # 会变的量放这儿,调度端按设备注入
  MSG: "你好"
---                               # ★ 这条分隔线必须有,整份文件只能有一条
- launchApp
- sleep: [2000, 4000]             # ★ 等待用区间,不用定值
- assertVisible: "首页锚点"        # ★ 锚点:没进对页面就停,别往下瞎点
- tapOn:
    text: "输入框"                 # ★ 全匹配正则,不是包含
    optional: true                # 可选元素找不到只记警告
- inputText: "${MSG}"
- tapOn: "发送"
- assertVisible: "已发送"          # ★ 顶层收口:任务成败在这里判定
```

四个 ★ 分别对应下面四条铁律。**把断言写在顶层**尤其关键 —— 嵌在循环或子流程里的失败不会冒泡。

## `${}` 在哪儿写,决定它什么时候算

同一个表达式,放在不同位置行为完全不同 —— 这是这套语法最容易翻车的地方:

| 写在哪 | 什么时候求值 | 意味着 |
|---|---|---|
| 普通命令的字符串字段 | 该命令执行前,每次都算 | 循环里每轮拿到新值 |
| `commands:` / branch 分支里的子命令 | 轮到它自己执行时才算 | `${Math.random()}` 每轮都不同,不会被冻住 |
| `while` / `when` 等条件 | 每次判断时重新算 | 计数器守卫能收敛,不会死循环 |
| `evalScript` / `runScript` 的脚本体 | **从不插值** | 那是代码,变量直接按名字用,写 `${x}` 反而是语法错 |
| `runFlow` / `retry` 内的 `defineVariables` | **从不插值** | 值原样存字面量;要算就改用 `evalScript` |

**顶层命令里 `${}` 求值失败会直接终止整个任务**,`optional` 和异常处理器都拦不住 ——
所以引用任何变量前先确保它被定义过。

## 工作流程

**1. 定规格,一轮问齐** —— **能自己上设备查的,一律别问用户。**
拿到主机 IP 和云机 ID 就能拼出设备地址(端口固定),包名、界面语言、每一屏长什么样、
怎么导航过去,你全都能自己拿(第 2 步)。真正只有用户知道的就两件:

| 必须问 | 为什么别处拿不到 |
|---|---|
| **要做什么**:任务目标 + 大致动作序列 | 意图不在设备里 |
| **主机 IP + 云机 ID** | 没有它你就是瞎的,只能产出占位脚本 |

**就这两样,别再多问。** 其余**你去查、或你来定**,给推荐让他点头,别开放式问:
包名、界面语言、当前在哪个页面(查);跑多久 / 多少次、单次批量上限、拟人化深度、
失败了停还是继续(定)。参数化默认按"账号 / 文案 / 目标数 / 时长全做成变量"来,不用问。

**红线也不用他先给** —— 危险元素(发送 / 关注 / 删除 / 发布)你从界面结构里就能认出来。
你的活是**主动列出来说"这些我都不碰"**,让他有机会否决或松口,而不是让他凭空想一遍。

**整理成摘要让用户确认 —— 这是硬闸,他点头才开工。** 摘要里必须含:你要做的动作序列、
你认定的危险元素、你替他定的那些参数。

用户来**排障**时要的是另一组:出问题的 YAML 原文、任务回执(哪条失败 / 跳过)、
现象("预期什么、实际什么")。**界面结构你自己去设备上取,别问他要。**

**2. 自己上设备探,一屏一屏来** —— 驱动同时提供界面结构、截图、shell 和输入通道,
所以查包名、查语言、抓每一屏、自己点过去,全都能做,**别把这些活推给用户**。
具体怎么查、抓到后当场做哪三件事,见 `references/device.md`。
**必须一屏屏来**:点下去才出现的弹窗和空态,一次性抓不到,漏了真机必崩。
探索用输入通道,**业务动作一律交给引擎跑** —— 手点没有选择器校验、没有随机节奏、没有异常兜底。

**3. 逐屏翻译成命令** —— 每屏一个原子循环,浏览型和操作型同一套,别按场景拆:

> **① 定位**稳定选择器 → **② 执行**动作 → **③ 校验**本屏独有锚点确认到位,没到别往下 →
> **④ 避危**认出这屏绝不能碰的元素(发送 / 关注 / 删除 / 发布 / 长按录音)并避开 → **⑤ 下一步**

所以"只浏览不互动""别删错"不是特殊安全模型,都是第 ④ 步的实例:每个任务有自己的危险元素集,纪律同一条。

**别从零发明结构** —— `references/patterns.md` 里有骨架和 9 个常用结构,
顶层锚点、有界收敛、随机等待、概率互动、顶层收口都已经摆好,抄来改选择器就行。
结构错了的代价见 `gotchas.md` §3,lint 也会在交付前拦一道。

**4. 过校验闸门** —— `python3 <本 skill 目录>/scripts/lint_flow.py 你的脚本.yaml`
(需要 python3 + PyYAML;`-q` 只看 ERROR,`--json` 输出结构化结果)。

**把它的结论当权威,别用手感覆盖它:**
- 报 `ok` 时**别再"保险起见"改写**已经通过的写法 —— 别补多余的引号、别到处加 `${}`、
  别给不需要的命令加 `optional`。过度防御会引入新问题(见 `gotchas.md`)。
- 报错时**只改它点名的那几条**,改完重跑。
- **同一条规则连续两次没修掉就停下来说明情况**,别靠猜继续试 —— 那通常意味着你理解错了那条规则,
  该回去读它对应的章节,而不是换个写法碰运气。


**5. 自己跑一轮** —— 你手里有设备地址,就有提交和看回执的全部手段(`runtime.md`),
别把验证推回给用户。**但这是真设备真账号,先过三道:**把批量上限调到最小(如 `MAX_NUM=1`)、
危险动作那段要用户明确点头、跑之前告诉他你要跑什么。
跑完对着逐条状态看:哪条 FAILED、哪片 SKIPPED、是不是全绿却没干活。这一步能发现所有静态检查发现不了的问题。

**6. 交付** —— 说清**哪几条真机验过、哪几条没验过**,占位选择器、已知边界、没覆盖的场景。别吹"稳了"。

## 四条铁律

**① 语法保真 —— 违反 = 脚本静默不跑,最要命。**
命令名和字段 shape 拿不准,一律回 `references/syntax.md` 核。这套语法里有整整一类写法**解析全过、任务报成功、
真机上什么都没干**:引用外部文件的子流程(路径从没被读过)、一个 `- ` 项里写了两个键(只认第一个)、
条件里写多个字段(只判第一个)。**没核过 shape = 没写完。**

**② 结构决定失败语义 —— 违反 = 出了错你也不知道。**
顶层命令失败会停掉整个流程;**但循环 / 子流程 / 分支【里面】的命令失败只停这个块,外面照常继续、任务报成功**。
所以关键断言必须放顶层收口。更狠的是:**顶层**命令里 `${}` 求值失败(引用未定义变量最常见)会绕过 `optional`、异常处理器、
失败回调,**直接终止整个任务**,步骤里连失败标记都没有 —— 引用变量前先确保它被定义过。细节见 `gotchas.md` §3。

**③ 通用 —— 违反 = 换台设备就废。**
坐标走百分比、选择器按**目标 App 的界面语言**取、会变的量(账号 / 文案 / 次数 / 时长)走变量由调度端注入,
别烧死在 YAML 里。

**④ 拟人化,无例外 —— 违反 = 被识别封号。**
每个脚本(含登录 / 发布 / 私信)都要底线:等待用随机区间、动作间有停顿。浏览 / 养号类再加深:
概率互动、深度停留、发呆。参数见 `references/humanization.md`。

## 别自我说服绕过

这三条是压力上来时最容易找的借口 —— 它们的共同点是**都能让你少做一步、而且当场看不出代价**:

| 你会想 | 现实 |
|---|---|
| "解析通过了就行" | 解析过 ≠ 真机能跑。有一整类写法解析全过、任务报成功、实际啥也没干。必跑 lint |
| "纯操作型脚本不用拟人" | 登录 / 私信 / 发布一样被风控识别,拟人底线人人要 |
| "界面结构一次全给我" | 点下去才出现的弹窗和空态抓不到,漏了真机必崩 —— 只能一屏屏来 |

具体的语法陷阱不在这儿凭记忆防,全表在 `gotchas.md`。

## 交付前自检

- [ ] lint **零 ERROR**,WARN 都看过?
- [ ] 关键成败判断在**顶层**收口,不是埋在循环 / 子流程 / 分支里?
- [ ] `${}` 引用的每个变量都**先被定义过**,不会炸掉整个任务?
- [ ] 会变的量是**变量**、能被调度端覆盖,没烧死?
- [ ] 等待都是**随机区间**?互动用概率而不是固定节拍?
- [ ] 坐标是**百分比**、选择器按**目标 App 界面语言**取?
- [ ] 选择器**稳**(唯一文本 + 正则剥掉计数),每屏有**锚点校验**?
- [ ] 每屏**危险元素**都认出并避开了?
- [ ] 循环**能收敛**,不会空转到迭代上限?可选元素带了 `optional: true`?
- [ ] 占位选择器都标了 `# TODO: 待真机界面结构替换`,并在交付说明里点名?

## 怎么跟用户配合

- **少废话,直接动手。** 要用户选就**给推荐**,推荐放第一个;中途有主意直接说"我建议 X,因为 Y",
  别甩问卷。带选项的结构化提问只用在开工前定规格。
- **别堆兜底,也别按场景打补丁。** 主干一条路 + 有界循环收敛,不为臆想的极端情况单开分支;
  同类动作一套写法 + 变量配置解决,别为每个页面复制粘贴一坨。**安全红线和锚点校验例外,那两样要留。**
- **老实交底。** 说清哪些真机验过、哪些是占位、哪些搁置了。
- **交付后留档**:这个 App 各屏的关键文字 / id、危险元素、页面锚点、踩到的坑 —— 下次或换人能直接用。

## 参考文件

**只读你这次任务真正需要的那几段。** 六份参考加起来一千多行,全读一遍既慢又会稀释注意力 ——
下面按任务类型给出该读什么,没点到的就别开。

**一次性必读(所有任务):** `references/gotchas.md`。
这套语法里有一整类写法能通过解析、任务还报成功、真机上却什么都没做,不知道它们你写什么都可能白写。
读一遍,后面出问题再回来查 §4 排障表。

**接下来按你要做的事分流:**

| 你要做的事 | 读这些 | 明确不用读 |
|---|---|---|
| 写一个新脚本 | `patterns.md` 挑一个最接近的结构 → `syntax.md` **只查你用到的那几条命令** | 用不到的命令章节;`runtime.md` |
| 排查一个跑错的脚本 | `runtime.md` 看回执定位到哪一条 → `gotchas.md` §4 症状对根因 | `patterns.md`、`humanization.md` |
| 元素点不中 / 要定选择器 | `device.md` 抓界面结构 → `syntax.md` §4 选择器规则 | 其余各节 |
| 定等待和概率 | `humanization.md` **§1 参数表**(所有脚本都要) | §2–§7 是浏览 / 养号专用,**操作型脚本不用读** |
| 要把脚本跑起来 / 取消 / 查进度 | `runtime.md` | 其余 |

`syntax.md` 是**查表用的,不通读** —— 用到哪条命令查哪条,§7 的默认值表在估超时和时长时才翻。

条件命中时**用 Read 工具真的去读,别凭记忆写**。这套语法里有一批命令和字段,凭印象猜出来的写法
能通过解析却不执行 —— 这正是这个 skill 存在的理由。

`scripts/lint_flow.py`:每次写完和改完都跑。
