# 跑起来:提交、看回执、取消

脚本写完不是终点。这份讲怎么交给引擎跑、怎么读逐条状态定位问题、怎么中止跑飞的任务。

---

**别把这两个地址搞混:探设备走驱动(18182),跑脚本和查进度走引擎(47218)。**

```bash
ENGINE=http://{主机IP}:47218                              # 引擎,默认端口
DEV=http://{主机IP}:18182/android_api/v2/{云机ID}          # 设备驱动,同 device.md

# 提交执行
curl -X POST $ENGINE/flow/execute -H 'Content-Type: application/json' -d "{
  \"yaml\": \"<整段 YAML>\",
  \"devices\": [{ \"baseUrl\": \"$DEV\", \"deviceId\": \"{云机ID}\", \"env\": { \"MSG\": \"你好\" } }]
}"
# → 查进度(按设备,不是按 taskId)
curl -X POST $ENGINE/flow/status -H 'Content-Type: application/json' -d '{"deviceIds":["{云机ID}"]}'
```

**接口按什么寻址,记这一条:运行中的任务按 `deviceIds`(查进度、取消),历史记录按 `taskIds`(删除)。**
因为一台设备同时只允许一个活跃任务,所以"这台设备现在在跑什么"本身就是唯一的。

其余接口:`/flow/list` 列任务 · `/flow/task/{taskId}` 查单个 · `/flow/delete` 删记录(收 `taskIds`)· `/health` 健康检查。
一次可以提交多台设备,每台一个 `devices[]` 项、各带自己的 `env`。

### 取消正在跑的任务

```bash
curl -X POST $ENGINE/flow/cancel -H 'Content-Type: application/json' \
     -d '{"deviceIds":["{云机ID}"]}'
```

返回里逐个设备给结果:设备没有在跑的任务 → `TASK_NOT_FOUND`;任务已经结束 → `TASK_CONFLICT`。

**取消是协作式的**,引擎在每条命令之前、循环每一轮、分支每个 arm 处检查取消信号:

- `sleep` 收到取消**立即返回**,长等待不会拖延取消 —— 养号脚本那种 `sleep: [3000, 8000]` 随便写。
- 元素查找、滚动查找、等界面稳定这些**内部轮询循环也逐轮检查取消**,所以最坏只等一次界面拉取的往返。
  **取消基本是秒级的** —— 如果点了取消迟迟没停,那是别的问题,别干等。
- 取消后任务标记为 CANCELLED,已经做过的动作**不会回滚** —— 这就是批量删除 / 发送类脚本
  必须做小批量、可续跑的原因。

⚠️ **轮询前先看清楚返回的是不是这次的任务。** `/flow/status` 查不到在跑的任务时,会**回落返回这台设备
最近一次已结束的任务** —— `found: true` + `status: COMPLETED` 可能是上一轮的结果,看着像"秒完成"。
拿提交时返回的 `taskId` 对一下,或者直接用 `/flow/task/{taskId}` 查。

**提交返回 HTTP 200 不代表都成功**,要逐项看 `results[].success`:
`40902` = 这台设备已有活跃任务(先取消或等它跑完);`42901` = 引擎并发已满(默认 10 个)。
而 **YAML 本身有语法错是整个请求 400**(`code: 40002`、`data: null`),不会逐设备报 —— message 里就是
具体的语法错误位置,直接照着改。

回执里**每条命令都有独立状态**,这是排障最有用的东西:

| 看到 | 说明 | 怎么办 |
|---|---|---|
| 某条 FAILED | 那条的选择器或条件不对 | 让用户切到那一屏重抓结构 |
| 一片 SKIPPED | 条件没成立,或变量名拼错求值成空 | 检查条件字段和变量名 |
| WARNED | `optional` 的元素没找到 | 通常无害;若在关键路径说明选择器写错了 |
| 卡在某条很久 | 元素找不到,在等超时 | 核实选择器,或确认那一屏真的会出现 |
| 全绿但没干活 | 失败被嵌套块吞了,或子流程空跑 | 见 `gotchas.md` §3,加顶层收口 |
| 明明界面上有,却报找不到 | 元素露出不足 10%,已被视野过滤剔除 | 先 `scrollUntilVisible` 滚出来再点 |
| 从某条起所有元素全找不到 | 设备界面结构拉不到时,引擎会静默替换成空界面 | 用驱动的 dump 接口自己验一下,必要时重启 App / 云机 |

两个容易误读的回执字段:`progress.completed` **把警告也算作已完成**,别拿它当"全绿"的判据;
任务级 `error` 是**最近一条失败命令**的错误,任务还在跑时就会出现,不是终态结论。

每台设备不同的量(账号、文案、目标数)放进各自的 `devices[].env`,一次提交给多台就各注各的。
这些注入值在脚本里是**只读**的,写法上要配合什么,见 `syntax.md` §1。
