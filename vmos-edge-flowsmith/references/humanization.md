# 拟人化

所有交互流程使用随机等待和可变手势；仅浏览、养号场景增加概率互动、深度停留和发呆。

**目录**：§1 参数 · §2 随机值 · §3 浏览节奏 · §4 概率互动 · §5 发呆 · §6 文案 · §7 风险边界

## §1 参数区间参考

起点值,按手感调:

| 场景 | 区间 |
|---|---|
| 点击 / 输入之间的小间隔 | `[500, 1500]` |
| 进入新页面先看一眼 | `[800, 2000]` |
| 刷视频 / 浏览单条停留 | `[3000, 8000]` |
| 深度停留(20~30% 概率) | `[6000, 15000]` |
| 发呆(~8% 概率) | `[15000, 40000]` |
| 等加载 / 等网络 | `[3000, 6000]` |
| 滑动手势时长 | `[200, 500]`(保留快甩) |
| 点赞概率 | 新号 0.1~0.15 / 老号 0.3~0.5 |
| 关注概率 | 0.02~0.08(最重的留痕) |
| 评论概率 | 0.05~0.1 |
| 单次批量动作条数 | 5~15,且必须可配 |

## §2 所有数字都别写死

真人和机器最大的破绽是"每次都一模一样"。等待、时长、次数、概率一律随机区间:

```yaml
- sleep: [3000, 8000]                              # ✅ 每次执行重新取值
- sleep: 5000                                      # ❌ 每次都 5 秒
- swipe: { direction: UP, duration: [200, 500] }   # ✅ 手势快慢也随机
```

`sleep` 和 `swipe.duration` 的区间都是**运行时**取值,每轮不同。
**例外**:`repeat.duration: [min, max]` 是解析期随机一次、整个循环沿用同一个值 —— 它决定"这轮跑多久",
本来就该固定。要"每轮不同"就放在循环体内用 `sleep`。

⚠️ 还有一层:一次 API 提交给多台设备时,整份 flow **只解析一次**,所以这个随机值**全批共用** ——
想让每台设备跑的时长不同,改成 `duration: "${RUN_MINUTES * 60000}"` 由调度端按设备注入。

## §3 节奏靠等待,不靠慢手势

真人一甩本来就快,把滑动做慢反而更假。节奏来自两处等待:

**进入一个新页面先停 `[800, 2000]` 再动手** —— 模拟真人进页面先扫一眼。这条最容易漏,加上立刻自然很多。

**方向**:信息流和列表往下浏览用 `UP`(手指上滑);看历史消息或评论要用 `DOWN` 下拉 ——
这类页面默认停在底部最新,上滑翻不到历史。

**有限列表要能停**:滑到底还在空滑一眼假。用 `while` 探"还没到底"的锚点,到底自动收敛。
**无限流**(短视频、推荐流)通常没有到底标志,别为不存在的锚点纠结,靠时长和次数收敛就够。

## §4 互动用概率,不用固定节拍

"每 5 条点一个赞"是机器行为。用 `chance` 让互动随机分布:

```yaml
- tapOn: { text: "点赞视频。.*", optional: true, chance: 0.4 }   # 单条命令挂概率

- runFlow:                                                      # 一组动作挂概率
    chance: 0.1
    commands:
      - tapOn: { text: "阅读或添加评论.*", optional: true }
      - sleep: [1200, 2500]
      - inputText: "${comments[Math.floor(Math.random() * comments.length)]}"
      - tapOn: { id: "send_btn", optional: true }
      - back
```

三条纪律:留痕动作(点赞、关注、评论、收藏)**一律带 `optional: true`**,找不到就跳过、别让整条流程失败;
选择器**用正则剥掉计数**(`"点赞视频。.*"` 而不是带具体数字的全文);`chance` 和 `when` **别同时挂**,
同时写时 `chance` 会被忽略。

**互动权重按账号定位分档**,别所有号一个样 —— 新号偏浏览、老号才敢多互动。把概率做成变量由调度端注入,
一套脚本跑不同档位。

## §5 偶尔发呆

留一个小概率的"整轮什么也不干",模拟真人放下手机走神:

```yaml
- runFlow:
    chance: 0.08
    commands: [ { sleep: [15000, 40000] } ]
```

## §6 内容别重复

群发同一句话是最容易被判垃圾的。建个库再随机取:

```yaml
- evalScript: "comments = ['好看', '不错', '哈哈哈', 'nice', '喜欢', '有意思']"
- inputText: "${comments[Math.floor(Math.random() * comments.length)]}"
```

文案库建议 8 条以上。注意表达式有 200ms 超时,别在里面写重活。

## §7 风控节奏比参数更重要

- **单次会话别贪长。** 一轮建议 20~40 分钟。引擎没有隐式次数或时长兜底，必须显式设置会话边界。
- **批量动作要有上限且可配**(私信、关注、删除),写成变量由调度端给,别烧死。
- **动作之间的间隔比动作总数更关键。** 连续 3 次点赞中间没停顿,比点赞总数多更容易被抓。
- **失败要能自然收敛,别死磕。** 批量循环配 `while` 条件,不成立就自动停 ——
  比"硬跑 N 次 + 一堆兜底"干净得多。
