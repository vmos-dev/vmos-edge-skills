# 上设备:查什么、怎么查、结构怎么变选择器

用设备结构和截图确定选择器，不凭视觉猜测。

**目录**:§1 自己上设备查 · §2 拿到后当场做三件事 · §3 为什么必须一屏屏

---

## §1 自己上设备查


通过设备驱动查询包名、界面语言、结构和截图，不向用户索要可直接发现的信息。

驱动地址是拼出来的,**默认端口 18182**,你只需要问到**主机 IP** 和**云机 ID**:

```bash
BASE=http://{主机IP}:18182/android_api/v2/{云机ID}   # 需要 curl 与 jq
X() { curl -sX POST $BASE/system/shell -H 'Content-Type: application/json' \
        -d "{\"command\":\"$1\",\"is_root\":false}" | jq -r .data.output; }
```

这个 `$BASE` 同时也是提交任务时 `devices[].baseUrl` 要填的值 —— 探设备和跑脚本用的是同一个地址。

| 要查什么 | 怎么查 |
|---|---|
| **当前前台是哪个 App / 哪个页面** | `X "dumpsys window \| grep -E 'mCurrentFocus\|mFocusedApp'"` |
| **目标 App 的包名** | `X "pm list packages \| grep -i tiktok"` |
| **设备 / 界面语言** | `X "getprop persist.sys.locale"`(拿不到就看 dump 里的文字是中是英) |
| **当前界面结构** | `curl -sX POST $BASE/accessibility/dump \| jq -r .data > screen.xml` |
| **界面长什么样** | `curl -sX POST $BASE/screenshot/format -o screen.png` |
| **自己导航过去** | `POST $BASE/input/click {"x":540,"y":1200}` · `/input/keyevent {"key_code":4}` 返回 · `/input/text` |

界面结构里每个控件带**文字、描述、资源 id、包名、边界坐标、可否点击** —— 这就是你写选择器的全部原料。
驱动响应是信封 `{code, msg, data}`,`code != 200` 就是出错了;shell 结果在 `data.output`,
另有 `data.exit_code` 和 `data.error`。

⚠️ **`is_root` 用 `false`。** 不少设备上没有 root shell,而它失败得**很安静** ——
HTTP 仍是 200、`msg` 仍是 OK,但 `exit_code: -1` 且**响应里根本没有 `output` 字段**,
`jq` 取出来是 `null`,看着像命令没输出。拿不到 output 时先把 `is_root` 换成 `false` 再判断。

**只有拿不到设备地址时**,才退回让用户一屏屏发截图或结构。这时每次**明确告诉他切到哪一屏、点哪个按钮**,
别甩一句"把界面发我"。这不是失败,是正常回退,但要跟他讲清楚:没有设备,选择器只能是占位。

⚠️ **输入通道只用来探索和导航,业务动作一律交给引擎跑。** 手点没有选择器校验、没有随机节奏、
没有异常兜底,发送和删除类动作尤其危险 —— 你在探索时误触一次,就是真实的账号损失。

## §2 拿到界面结构后,当场做三件事


> 还没有真实结构、先搭骨架时:选择器写合理占位,但**显式标 `# TODO: 待真机界面结构替换`**,
> 交付时点名提醒。别把占位当真选择器交出去。

**1. 挑稳定选择器。** 优先唯一文字 —— 注意匹配是**全匹配正则**,要"包含"得自己写 `.*`。
文字会变(带计数、多语言)就用正则剥掉变化部分;文字不唯一就用空间关系或父容器收窄;
实在没有稳定文字才退到资源 id(易随版本变);最后才是百分比坐标。选择器按**目标 App 的界面语言**取。

**2. 标出危险元素,主动告诉用户你会避开。** 这屏哪些控件点了会闯祸:发送、关注、转发、删除、发布、
长按录音、改设置开关。当场列出来说"这些我都不碰",让用户有数、能否决。滑动的起止点也要避开这些区域。
真机探索期间不得触发这些动作。

**3. 定锚点。** 找一个"确认真到了这一页"的独有元素,别用会串页的内容行。必须到就写顶层断言,
可能没到就写条件执行。**没有锚点校验的流程是盲的**:错一屏,后面全错位。

### 例:一段界面结构怎么变成命令

```
控件A  文字="关注 1.2万"   id=follow_btn   可点击   边界=[880,1180][1010,1240]
控件B  描述="点赞视频。1.2万个赞"  id=like_btn   边界=[900,1300][1010,1400]
控件C  文字="推荐"  id=tab_rec  边界=[420,120][540,180]
```

- **锚点**:`assertVisible: "推荐"` —— tab 文字唯一,且不随内容变。
- **危险元素**:`follow_btn`(关注 = 留痕)。告诉用户"默认不碰,要碰你说"。
- **选择器**:点赞用 `text: "点赞视频。.*"` —— 描述里带计数会变,正则剥掉;不用 `like_btn` 这种
  混淆过的 id。再配 `optional: true`,因为不是每屏都有。

## §3 为什么必须一屏一屏


点下去才出现的东西,批量甩过来根本抓不到,漏了上真机必崩。常踩的:

- **首次弹窗**(权限 / 条款 / 引导)只第一次出现 → 要么进异常处理器,要么写成条件执行。
- **空态页**:列表为空时长得完全不一样,危险按钮常就在那。
- **入口在列表底部**:得滚出来才能点,硬点看不见的元素必失败。
- **相邻页预加载**:判断"当前在哪页"不能用内容行,要用该页独有元素。

每次页面变化后重新获取结构，不复用上一屏的假设。
